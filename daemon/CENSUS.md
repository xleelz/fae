# Reviewed retirement census

`fae census [--include-blocked] [--file proposals.json]` is read-only. It returns a format-1 artifact containing every included task's state, durable version and payload digest, current branch tip (or explicit read error), task-owned landing SHA, proposed reason and evidence. Without a validated task-owned landing artifact the default classification is live. Branch ancestry never supplies containment evidence.

Optional proposals are a JSON array of `{ "id": "task", "reason": "superseded-by successor", "evidence": "operator acceptance-coverage judgment and reference" }`. Obsolete proposals require a ruling reference in the reason and explicit evidence. Supersession requires an existing successor; semantic acceptance coverage remains an explicit operator judgment, never an automated inference. Contained proposals must pass the existing exact-SHA/task-owned evidence guard. Missing tasks, duplicate proposals, malformed reasons and absent evidence refuse the census. Blocked tasks can be reported, but retirement still requires the existing Escalated state: census does not silently escalate tasks.

Review the artifact, then run `fae census apply --file census.json --authorizing-message MESSAGE [--gap 2s]`. The CLI validates the complete artifact before beginning, skips live rows and calls the one-row `CensusApply` RPC in artifact order. Each call supplies the full artifact and `row_id`; it revalidates the checksum, instance, version and payload digest and enters the normal authorized `Retire` boundary. The checksum detects edits, not signatures: artifacts are untrusted operator input and retirement evidence is rechecked at enactment. Every successful retirement audit cites the same message, its own reason/evidence and the census digest. SQL serialization retries use the existing bounded transaction retry policy; any final error stops the CLI and prints completed IDs, failed ID and error before exiting nonzero.

Pacing defaults to two seconds outside the daemon mutex and RPC deadline, so the drive can continue between rows. Each row is independently atomic; the batch is deliberately not a transaction. Reapplying a completed row fails stale rather than generating a second audit. After a crash or failure, collect a fresh census for remaining tasks. RPC response loss may leave the last retirement committed even when it is not in the CLI's completed list; authoritative state and audit resolve that uncertainty. Artifacts are limited to 1,000 rows, reasons/evidence to 4 KiB each, and the transport's existing request bound still applies. Persist the printed JSON locally for review; the read operation does not write the plane.

The production version-and-digest guard is covered by Gobra with a weakened negative control; the Gomela model checks snapshot acknowledgement before retirement. Native tests cover ten independently audited retirements, stale versions, missing rows/authority, no automatic classification of scripted or unproven work, and refused replay. CLI tests cover complete-artifact validation and clear partial progress on a failed row.
