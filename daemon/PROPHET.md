# Prophet sessions

`fae prophet chat --task ID --text TEXT` queues a bounded, asynchronous turn and returns its message ID. `fae prophet session --task ID --after N --limit 100` reads durable chat pages and task context; `fae prophet global --text TEXT` queues an instance liaison turn, and `fae prophet global --after N` reads its conversation. Replies identify the original message in `reply_to`. Each entry has an author, daemon-recorded time and monotonic per-scope sequence. Chat reads report queued/completed/failed turns; old daemon queued turns are explicitly interrupted and never automatically replayed.

Per-task prompts contain only the pinned task workflow, a bounded content excerpt, the latest 100 evidence/history/context entries with explicit history and artifact offsets/counts, disposition, and that task's most recent 100 chat entries. Global prompts contain compact task/workflow/state/disposition summaries and daemon health, plus the latest 100 molecule identities/revisions and 20 persisted alerts with explicit overflow flags. Read pages are capped at 2 MiB and turn context is limited to 1 MiB, chat input to 64 KiB, and output to 1 MiB with bounded reply/action fields. Larger histories must be inspected through paging; an oversized context fails before launch rather than silently losing task evidence.

The live path runs a fresh, handoff-only ordinary provider session through the existing weighted host and Herdr pane admission/reaping machinery. Its empty workflow role table cannot acquire any workflow role slots. The bridge receives a private empty directory, no configured repository files, no tool capabilities, and no resumable provider context. The binding is configured with `serve --prophet-provider` (default `codex`) and `--prophet-model` (default `gpt-6-astra`). `--prophet-routes FILE` optionally supplies an ordered JSON array of up to eight unique provider/model bindings (with optional effort); when absent the fixed flags remain the default. Routes share the durable workflow provider-health rows and structured log classifier. Every attempt selects the first eligible remaining route, persists its typed outcome, and confirms process retirement and lease release before any failover. `--prophet-max-failovers` defaults to one (zero selects that default), accepts 1..7, and -1 disables failover. Invalid output is classified as malformed; pre-provider failures do not penalize provider health. Unreadable health, uncertain observation persistence, or unconfirmed cleanup fail closed. If all routes are unhealthy the conversation records a failed reply without launching; a new explicit operator message is required after recovery. Failed or interrupted chats are never automatically replayed. Conversation continuity comes from durable plane messages rather than an opaque provider memory. Tests can install a trusted scripted `Config.ProphetRunner` to inspect the exact scoped brief.

Proposals are text only. To allow an action, the operator explicitly supplies `--direct RestartWithInformation` or `--direct ResumeWithContext`; a global command additionally requires `--action-task ID`. Only those two actions are allowed, and the generated action must match the exact structured operator scope. The daemon records the structured directing message, then invokes the existing task-control implementation as actor `prophet`, citing that message. Unsupported, undirected or cross-task actions produce a refused reply. No Prophet can approve code, waive a gate, alter governance, create a quality disposition, or submit operator messages through delegated credentials.

Chat submission returns before provider execution; poll pages for the response. Runtime cancellation/restart preserves the request and conservatively reports interruption; no automatic re-execution of a potentially acted-on request occurs. A reply checkpoint failure is logged and the durable queued record remains an unresolved outcome. Transcript storage currently uses immutable blob-backed plane marker entries and is not physically compacted. Task-scoped external operator-message citations are not enumerated: only scoped chat and appended context are included, avoiding leakage from a broad grant shared across tasks.
