# Working on Fae

Record requested new Fae features in Linear before implementing them, so Fae can
implement its own features through its intake workflow.

- Team: OpenRelay Engineering (`OR`).
- Project: Fae Testing (`2fbea0e2-6abc-4838-a844-a4599d606390`).
- Create or update an issue with the requested behavior, acceptance criteria and
  explicit blocking dependencies. Reuse an existing issue when it covers the work.
- Keep exploratory or underspecified requests in Backlog. Put actionable work in
  Todo with the `Fae` label when it is ready for automatic intake.
- Use Linear blocking relationships for execution order; hierarchy alone does
  not establish a dependency.

For Herdr UX work, read `~/.config/herdr-app/AGENTS.md` and the installed type
definitions before editing. Preserve personal layouts and keybindings, and run
`herdr-app check` plus a visual check before calling a mod complete.

User instructions and explicit exceptions take precedence over this workflow.
